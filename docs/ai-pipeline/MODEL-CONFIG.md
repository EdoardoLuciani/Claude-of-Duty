# AI Pipeline — Model Configuration (verified)

The pipeline pins its agent tooling and verifies model settings rather than
assuming them (spec §6, §36).

## Implementation agent — DeepSeek V4 Flash / max

| Setting | Value | How it is pinned / verified |
|---|---|---|
| Harness | pi (`@earendil-works/pi-coding-agent`) | `engine.version: 0.84.1` in `agent-implement.md`/`agent-fix.md` → compiled lock installs `npm i -g @earendil-works/pi-coding-agent@0.84.1` |
| Driver | vendored `.github/drivers/pi-opencode-go-driver.cjs` | adapted from gh-aw v0.85.4; version-checked against pi-agent-core 0.84.x at runtime |
| Provider | `opencode-go` (OpenCode Go, BYOK) | base URL `https://opencode.ai/zen/go/v1` (verified in models.dev and pi-ai 0.84.1 bundled catalog `providers/data/opencode-go.json`) |
| Credential | `CODEX_API_KEY` env (secret) | the exact env var the pinned gh-aw pi engine (`codex` backend) emits; value is the OpenCode Go key |
| Model | `deepseek-v4-flash` | `AI_PI_MODEL`; model metadata copied from pi-ai 0.84.1 catalog (context 1M, maxTokens 384000, thinkingFormat `deepseek`) |
| Reasoning effort | **`max`** | `AI_PI_THINKING: max`; `thinkingLevelMap: { high: "high", max: "max" }` — `max` is the highest variant exposed by deepseek-v4-flash (models.dev: `reasoning_options: effort [low, high, max]`) |

Verification performed:

- models.dev (`/tmp` query of the public catalog): `opencode-go/deepseek-v4-flash`
  exposes `reasoning_options: [{"type": "effort", "values": ["low","high","max"]}]` —
  `max` exists, nothing higher.
- pi-ai 0.84.1 bundled metadata matches (see driver header comment).
- The driver was exercised end-to-end against a mock OpenAI-compatible server:
  request carried the model id, `Bearer` auth from the secret env, streaming
  tool calls, and the bash tool executed with a credential-scrubbed env.
- The compiled workflow's execution step env includes `GH_AW_PI_MODEL`,
  `AI_PI_MODEL: deepseek-v4-flash`, `AI_PI_THINKING: max` (grep the lock file
  to confirm at any time).

If the provider/model configuration is ever changed, the rule is: verify the
new model's actual reasoning variants before picking an effort level; never
invent an unsupported value; document discrepancies in the PR.
