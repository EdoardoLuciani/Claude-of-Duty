## Matched combat profile

Same Ryzen 9 9950X, hardware AMD RDNA 4 WebGPU (not fallback), Fedora 45 / Mesa Vulkan 26.2.7, Bun 1.4.5, Playwright 1.65.1 and headless Chrome for Testing 153.0.8010.12. Used #806's `tools/profile.ts` command unchanged: dev build, `living-combat-v1`, five opponents, High, 1280×720, DPR 1, no rail, 120 warmup and 1,800 measured frames. Runs were sequential with unpaced browser callbacks and a fixed 60 Hz simulation. Values below are **p50 / p95 / p99 / max** in milliseconds.

All four runs validated living combat: 54 player shots, four switches and four completed reloads each; AI shots were 410/409 on the baseline and 410/410 on the release. All had zero frame hitches, callback hitches, CPU budget misses, measured node builds or browser errors. GPU frame/presentation time was not measured.

**Tail investigation:** both initial release runs had higher CPU-game maxima. Two additional uninstrumented pairs on the same machine gave baseline/release maxima of **3.1/5.1 ms** (baseline first) and **5.1/4.8 ms** (release first). With `--detail` enabled on both SHAs, both peaked on frame 424 with the pistol active, not reloading, and no shots that frame (5.2/5.8 ms). The peak is real, but not specific to the release; the difference did not survive reversing run order, and no run hit the CPU budget. These are comparisons, not CI timing thresholds.

## What actually changed

- [Attachment rules (#828)](https://github.com/EdoardoLuciani/Claude-of-Duty/pull/828) and [import guard (#831)](https://github.com/EdoardoLuciani/Claude-of-Duty/pull/831): `src/ui/market-stats.ts` calculates effective stats with `buildDef` from `attachment-rules.ts` without importing mounting or asset loading. Lint protects this specific runtime boundary. Type imports and worker-owned physics queries remain legitimate.
- [Hand equipment (#829)](https://github.com/EdoardoLuciani/Claude-of-Duty/pull/829): `smoke-weapons-input-context.ts` instantiates `HandEquipment` directly and checks that a committed release can be consumed only once, without a viewmodel, player or world. [Shared grenade lifecycle (#830)](https://github.com/EdoardoLuciani/Claude-of-Duty/pull/830) and [event snapshots (#834)](https://github.com/EdoardoLuciani/Claude-of-Duty/pull/834) keep launch logic owner-specific; the player and AI smokes check event attribution and removal of spent bodies.
- [Route results (#832)](https://github.com/EdoardoLuciani/Claude-of-Duty/pull/832): `Agent._goTo` branches on the return from `requestPath`, not shared `AiSystem.lastPath*` fields. `SurfaceNav` still exposes solver diagnostics; `AiSystem` copies them into caller-owned storage on completion. `smoke-ai-combat.ts` checks caller isolation and preserved waypoints/diagnostics across budget and real-worker deferrals, waiting for the eventual result rather than assuming the frame it arrives.
- [Ladders (#811)](https://github.com/EdoardoLuciani/Claude-of-Duty/issues/811): the proposed extraction needed the entire agent or callbacks into its identity-based occupancy checks, so it was declined. [#836](https://github.com/EdoardoLuciani/Claude-of-Duty/pull/836) merged only the real-worker traversal tests. They cover handover after one agent owns the shaft, not recovery from simultaneous arrivals; the pre-existing two-agent stall reported there remains outside this check.
- [Authored adapters (#835)](https://github.com/EdoardoLuciani/Claude-of-Duty/pull/835): ejection timing lives with the animation and audio maps the shared close cue to the weapon-specific recording. No general adapter factory: the common setup did not justify abstracting per-model animation and material ownership. Reload telemetry no longer includes `retained`, and the pistol close phase is now `boltclose`.
