# MPX authoring: source first

Edit `../mpx.py` and `../mpx_actions.py`, then regenerate the whole weapon.
The packed `mpx.blend`, runtime GLB, three PNG maps and manifest are generated
products, never fallback inputs. Normal Vite builds use the committed GLB and
need no Blender or network access.

## Edit map and stages

| Concern                                                          | Local edit location                                               |
| ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| Build/reset, output paths and stage order                        | `../mpx.py`: `build` / `main`                                     |
| Three seeded maps and named physical finishes                    | `../mpx.py`: `field`, `image`, `material` and finish declarations |
| Geometry, controls, markings, optics, sockets                    | Matching named assembly sections of `../mpx.py`                   |
| Original per-component smart-project atlas                       | End of component construction in `../mpx.py`                      |
| Eight clips, wrist/finger poses, visibility and events           | `../mpx_actions.py`: `author_actions`                             |
| Runtime-only 120 Hz preparation                                  | `animations.py`: `prepare_export_actions`                         |
| Frozen cameras/lights/exposure and optional renders              | `../mpx.py`: `camera`, `area` and studio setup                    |
| Evaluated rigid copies, stock native export and read-only checks | End of `../mpx.py`                                                |

Imports do not build or reset the scene. `build` starts from a factory-empty
scene, generates maps/materials and component meshes in the original assembly
order, projects markings onto their declared surfaces, and keeps the existing
per-component smart-project atlas. Do not substitute MCX planar UVs, a new atlas,
new geometry or different optical finishes under an authoring cleanup.

Actions and excluded review skins are authored before the packed editable preview
is saved with Idle selected. Runtime copies then evaluate modifiers and join only
components sharing one rigid parent. The preview retains its components,
modifiers, sparse Bezier poses and unchanged review-hand actions.

Runtime-only actions retain the historical **120 Hz** effective sample lattice.
The last sample comes from `ceil(duration * 120)` and receives the exact duration
as its source key time, including **60/950 seconds** for Fire/Last_Shot. This
preserves the old held endpoint value, not a newly resampled endpoint. Scales are
CONSTANT on that same lattice and export as STEP. Explicit TRS channels preserve
clip switching and reset semantics, including child resets under hidden parents.
The ordinary stock Actions exporter reads prepared curves without forced
sampling. The output is opened only for read-only assertions/counts; there are no
GLB repairs, exporter hooks or shared-helper changes.

## Declared read-only inputs

- `assets/weapons/sig-mpx/hand-reference.json`: versioned wrist/finger calibration
  generated by `tools/mpx-hand-reference.mjs` from shared runtime Arm calibration
  and MPX contact constants. Ordinary rebuilds **do not refit hands**. Regenerate
  this input only for an explicitly approved calibration change.
- `assets/player/arms/player-arms.blend`: shared appearance/bind data appended
  through the existing frozen `evolys_actions.author_review_hands` helper for DCC
  review only. Review skins/armatures are excluded from the runtime GLB.
- Blender 5.2.2, its stock glTF exporter, bundled NumPy/default font and a working
  compatible OCIO configuration. Missing inputs fail; old MPX assets are not read.

## Build and validate (repository root)

```sh
blender -b -t 4 --python-exit-code 1 --python tools/blender/mpx.py -- \
  --output /tmp/mpx-review
# Optional GPU review; --quick only reduces preview resolution/samples:
blender -b -t 4 --python-exit-code 1 --python tools/blender/mpx.py -- \
  --output /tmp/mpx-review --render --quick
blender -b -t 4 /tmp/mpx-review/mpx.blend --python-exit-code 1 \
  --python tools/blender/mpx_check.py
node tests/smoke/smoke-mpx-asset.mjs
node tests/smoke/smoke-mpx.mjs
npm test
npm run lint
npm run build
npm run format:check
```

Without `--output`, products go to `assets/weapons/sig-mpx`. Renders, only when
requested, go to `OUTPUT/renders`. `--quick` never changes maps, geometry, UVs,
animation, runtime export or manifest. Supply a compatible process-local `OCIO`
if needed; never compensate with changed lights/exposure or disabled transforms.
Compare source renders with matching cameras, pose, lighting and exposure.

## Explicit reproducibility limit (preserve the original atlas)

Fresh Blender 5.2.2 builds exhibit tiny numerical variation in evaluated bevel UV
interpolation even with byte-identical saved-source component UVs. The measured
maximum is **1.1920928955078125e-7 UV**, or **0.0001220703125 texel** on the 1024²
maps. This also occurs in the unchanged historical recipe; a single-thread build
does not eliminate it. The user explicitly selected atlas preservation over UV
rounding. **GLB byte-repeatability is therefore unmet for those UV bytes.** No
rounding, reprojection, repacking, seam collapse or custom interpolation is used.
The seeded PNG maps and manifest repeat exactly; all non-UV runtime payloads must
still compare exactly between fresh builds. The factory-empty migration also
removes the old startup cube's orphan mesh datablock: three incidental glTF mesh
labels shift from `Cube.131/.166/.117` to `Cube.130/.165/.116`. Authored node,
control, socket and rigid-parent names do not change; runtime lookup uses those
names, not automatic mesh-datablock labels. This is a measured environment limit,
not a blanket cross-platform identity or appearance claim.

For verification, use two empty external output directories and fresh Blender
processes under the same declared environment. Compare GLB, map and manifest
hashes and isolate differing bytes to evaluated UV accessors rather than ignoring
whole geometry or using a broad tolerance. Blend metadata can contain output
paths. For preservation, compare actual
geometry/index/normal/UV payloads, material parameters/embedded maps, nodes and
sockets, clip/event data and fractional-time motion/visibility/hand/reset behavior.
A successful export or source check does not grant Gate 3 human visual/gameplay
acceptance. Keep the limitations in the asset README.
